# Editor and Runtime Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide English, Traditional Chinese, and Simplified Chinese for the editor, play mode, presenter, and runtime controls, following the browser language by default and remembering a manual choice.

**Architecture:** A typed dictionary and `LocaleProvider` in the editor supply `t(key, vars)`. Runtime strings live inside `RUNTIME_SOURCE` because exported decks have no editor context. The presenter popup receives its resolved strings as JSON in a body data attribute because `PRESENTER_CLIENT` is serialized with `toString()` and cannot close over outer variables. Playwright runs the existing Chinese suite under `locale: 'zh-TW'`; new tests opt into other locales.

**Tech Stack:** TypeScript, React 19 context, Vitest, Playwright, the string-only runtime.

**Spec:** `docs/superpowers/specs/2026-10-23-editor-open-url-i18n-design.md` (section 3)

## Global Constraints

- Locales: `en`, `zh-Hant`, `zh-Hans`. No new dependency and no pluralization library.
- Message keys are `keyof typeof en`; the other dictionaries are `Record<MessageKey, string>` so missing or extra keys fail typechecking. A unit test also compares key sets.
- Interpolation uses `{name}` placeholders. Unknown keys return the key.
- Detection: `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant*` → `zh-Hant`; `zh-CN`, `zh-SG`, `zh-Hans*`, other `zh*` → `zh-Hans`; `en*` → `en`; anything else → `en`.
- `localStorage['htmlppt.locale']` wins when valid. Changing locale updates `<html lang>` immediately.
- CLI and MCP output stay English. Host API error payloads stay English; the editor maps known codes and falls back to the raw message.
- Core/command error details that are technical fallbacks may remain English, but every static label, title, aria-label, placeholder, announcement, and status must use the provider.
- Runtime `String.raw` cannot contain backticks or `${}`; use single-quoted strings and concatenation.
- Phase 3 starts only after Phase 2 has a green hosted CI run.
- Existing Chinese assertions must keep asserting Chinese; do not loosen them.

```tsx
import {
  createContext,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useState,
  type ReactNode
} from 'react';
import { en } from './messages/en';
import type { MessageKey } from './messages/en';
import { zhHant } from './messages/zh-Hant';
import { zhHans } from './messages/zh-Hans';

export type Locale = 'en' | 'zh-Hant' | 'zh-Hans';
export type Translator = (
  key: MessageKey,
  vars?: Record<string, string | number>
) => string;

export const LOCALE_STORAGE_KEY = 'htmlppt.locale';

const DICTIONARIES: Record<Locale, Record<MessageKey, string>> = {
  en,
  'zh-Hant': zhHant,
  'zh-Hans': zhHans
};

const VALID_LOCALES = new Set<Locale>(['en', 'zh-Hant', 'zh-Hans']);

export function detectLocale(language: string): Locale {
  const value = language.toLowerCase();
  if (value.startsWith('zh')) {
    if (
      value === 'zh-tw' ||
      value === 'zh-hk' ||
      value === 'zh-mo' ||
      value.includes('hant')
    ) {
      return 'zh-Hant';
    }
    return 'zh-Hans';
  }
  return 'en';
}

export function resolveInitialLocale(
  storage: Pick<Storage, 'getItem'> = localStorage
): Locale {
  let stored: string | null = null;
  try {
    stored = storage.getItem(LOCALE_STORAGE_KEY);
  } catch {
    stored = null;
  }
  if (stored && VALID_LOCALES.has(stored as Locale)) {
    return stored as Locale;
  }
  return detectLocale(navigator.language);
}

function interpolate(
  template: string,
  vars?: Record<string, string | number>
): string {
  if (!vars) return template;
  return template.replace(/\{(\w+)\}/g, (match, name: string) =>
    Object.prototype.hasOwnProperty.call(vars, name)
      ? String(vars[name])
      : match
  );
}

interface LocaleContextValue {
  locale: Locale;
  setLocale: (locale: Locale) => void;
  t: Translator;
}

const LocaleContext = createContext<LocaleContextValue | null>(null);

export function LocaleProvider({
  children,
  initialLocale
}: {
  children: ReactNode;
  initialLocale?: Locale;
}) {
  const [locale, setLocaleState] = useState<Locale>(
    () => initialLocale ?? resolveInitialLocale()
  );

  const setLocale = useCallback((next: Locale) => {
    setLocaleState(next);
    try {
      localStorage.setItem(LOCALE_STORAGE_KEY, next);
    } catch {
      // Storage may be unavailable in private or static contexts.
    }
  }, []);

  useEffect(() => {
    document.documentElement.lang = locale;
  }, [locale]);

  const t = useCallback<Translator>(
    (key, vars) =>
      interpolate(DICTIONARIES[locale][key] ?? en[key] ?? key, vars),
    [locale]
  );

  const value = useMemo(
    () => ({ locale, setLocale, t }),
    [locale, setLocale, t]
  );

  return (
    <LocaleContext.Provider value={value}>{children}</LocaleContext.Provider>
  );
}

export function useI18n(): LocaleContextValue {
  const value = useContext(LocaleContext);
  if (!value) {
    throw new Error('useI18n must be used inside LocaleProvider');
  }
  return value;
}
```
